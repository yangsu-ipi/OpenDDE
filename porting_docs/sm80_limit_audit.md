**Tier 2: retain the sm_120 values, with one decision for the user.** Every harmless contrast on this host passes every gate on every development job under the sm_120 limits (kernel 16/16, precision 15/15 with D4 absent, `fast_layernorm` 16/16, Zn qualified in all three), and every negative control fails on every applicable job except D1 jitter (below). The decision is the same-outcome lDDT limit of the flexible class:

- **Option A: 0.95 (the sm_120 value).** The kernel swap passes it on D3 and D13 `1a14_unconstrained` by 0.0026 (0.9526) and `fast_layernorm` by 0.0058; the archived host's three harmless contrasts all failed it there (0.947-0.950).
- **Option B (recommended): 0.92**, C9's written doubling rule applied to this host's precision contrast for the flexible class (worst deficit 0.0349 on D3, doubled and rounded up to 0.08). It applies to the all-polymer and per-type lDDT gates of D3, D11, D12 and D13 `1a14_unconstrained`; D8 keeps its 0.85 override, and the held-out flexible rows (H1-H4, H7) already use their own 0.85, so held-out gates are unchanged. Under 0.92 no verdict changes: all harmless contrasts still pass, and the hinge and jitter controls on the flexible rows (lDDT 0.83-0.875) still fail this gate as well as 4-5 others each. Reason to prefer it: a harmless candidate's lDDT on the 1a14 inputs sits within 0.003 of 0.95 on this host and below it on the previous one, and a false failure on a development row costs a rehearsal or, at acceptance, a held-out draw.

Either option leaves every other sm_120 tier 2 value unchanged, so the sm_80 limit file would differ from sm_120's in that one class value (option B) or not at all (option A), plus its `gpu` and status fields.

## Reduced assurance and gaps carried into any sm_80 claim

1. **D4 precision.** No fp32 contrast fits on 80 GB in either tested recipe, at tier 1 or tier 2. D4's limits rest on the kernel swap and `fast_layernorm`; the same gap applies to H10 (same input size).
2. **D1 jitter.** D1 does not detect uniform 0.5 Å noise; it detects gross failures only.
3. **Kernel-set limits** (three groups above): calibrated on the kernel swap. The predeclared contrast tested two of them informatively (flexible/epitope fnonnat rise, low/stable spread ratio) and left the third (median lowest per-chain-pair reference Fnat drop, 0.05) unmoved, so that limit has no independent harmless test on sm_80.
4. **Flexible interface Fnat 0.55**: set after inspection on sm_120; no independent harmless check except the predeclared contrast.
5. **D10 eligibility**: 0-1 same-outcome pairs per contrast.
6. **Host drift**: the same GPU model with a different driver changed stock `off` on the larger inputs (1a14, 7wux), first in the trunk. The limits and baseline are this host's; a further host change needs E6's acceptance test again.
7. **Validation strength**: measured (below): 26 gate groups informative, 5 weak, 2 untested (the median lowest per-chain-pair reference Fnat limit and the Zn same-site fraction).
8. **Retention**: the NAS copy is checksum-verified against retained source manifests, but not protected (E5).
